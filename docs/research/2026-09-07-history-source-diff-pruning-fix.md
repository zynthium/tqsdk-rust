# 历史 source DIFF 裁剪修复验证

## 根因与修复

消费后清空整个 series.data，再复用连接读取重叠窗口，破坏客户端与服务端的增量 DIFF 状态一致性。
服务端只发送新增尾部；缺行可能报错，也可能被误判 terminal 并写入 final coverage。

修复仅裁剪已消费末行之前的 ID，保留边界与预取；裁剪过的连接不回池。
一个 fill source 仅接受一个 chart。同一 chart 内分页仍使用原连接。
canonical minute/daily 同时验证窗口首尾存在，不要求内部 ID 连续，不修改 Tick 稀疏语义。
这是 source 生命周期契约修正，不新增 public API 或改变 crate 所有权。

## 性能与后续边界

32 页离线回归验证裁剪保留一条重叠行及 17 条预取行，不随页数累积。
该上界针对正常固定窗口协议，不是对异常无限预取数据的防御承诺。
本地裁剪后不复用连接会增加 slice 间鉴权/连接成本；优先保证 final coverage 正确，暂不引入
第二套原始 DIFF 缓存或复杂复用协议。

生产 Tick 仍使用旧进程；未得到暂停确认前不停止。修复不会撤销既有错误 final 标记。
后续需优雅暂停旧进程、定向重建受影响缓存、重新审计候选 session/例外并发布 Timeline，
再恢复新版补数。不得把当前隔离验证当成八个品种的生产全范围激活完成。
